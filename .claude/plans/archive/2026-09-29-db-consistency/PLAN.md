# Database consistency

Written 2026-09-29 from the live TEST schema (`imhinsgyzzyblghwnedk`), read-only. Nothing here is applied anywhere yet.

The target: every table says what it holds, every child row points at its parent by id, one word per concept, and every timestamp is `timestamptz not null`.

## Naming rules

- **The owning user is always `user_id`.** Never `owner_id`, `created_by` or anything else, in tables, policies, functions and the Drizzle schema.
- A link to a parent row is `<parent>_id` and points at the parent's `id`, never at a slug or name.
- Creation and change times are `created_at` / `updated_at`.

## Implemented: batch 1

All "Do" items plus the two approved links are in **one** migration, `supabase/migrations/20260929120000_schema_consistency.sql`. It runs as one transaction, so no half-renamed schema is ever live, and every function is recreated once against the final names. It replaced the two earlier drafts (`…_ai_credits_table.sql`, `…_qr_configs_catalogue_id.sql`).

Order-sensitive details:
- Bad values are reported up front in one error.
- Data fixes on `catalogues` and `qr_configs` run with the touch trigger disabled, so they don't look like owner edits.
- Names are looked up by prefix, as in M03.

## Rollout

1. **Package.** Release `@quicktalog/common` with the regenerated schema. After the TEST push, run `drizzle-kit pull` against TEST and confirm it matches, apart from table order.
2. **TEST.**
   - `supabase db push`.
   - Deploy the app (`test`) and the worker right after: the running app uses `created_by`, `newsletter` and `qr_configs.catalogue`, which the migration removes, so the two must go out together.
   - The worker only runs daily, so it has until the next run.
3. **PROD pre-checks** (read-only):
   - `select distinct source from catalogues`;
   - `select distinct subscription_status from subscriptions`;
   - `select scheduled_change from subscriptions where scheduled_change !~ '^\d{4}-\d{2}-\d{2}T'`;
   - catalogue slugs in `analytics.current_url` that match no catalogue (those rows keep a null `catalogue_id`).
4. **PROD edge functions.**
   - Read them for `newsletter`, `product_newsletter`, `created_by`, `owner_id`, `analytics.date`/`pageview_count` or `scheduled_change` as text.
   - The `contacts` and `active_subscriptions` views keep their output columns.
   - Webhook payloads from `users`/`subscriptions` gain `updated_at`, and `scheduled_change` becomes a timestamptz string.
5. **PROD** in a maintenance window, same order as TEST, before the auth cutover (the cutover scripts expect the new names).
