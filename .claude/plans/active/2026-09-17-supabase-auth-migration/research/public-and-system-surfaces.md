# Public and system data access paths

> Phase-1 report produced on 2026-09-16 while preparing `../PLAN.md`. It reflects branch `test` at `fcee862` and read-only queries on the TEST project. Where it disagrees with `../PLAN.md`, the plan wins.

## Non-owner data access in quicktalog-app (test branch @ fcee862), the worker, and the DB

### TL;DR for the migration plan
1. **Nothing public reads `users`, `subscriptions` or `plans`.** A public catalogue page only needs `catalogues` rows with `status = 'active'` (gate at `app/catalogues/[name]/page.tsx:142`). Plan features are saved into the catalogue JSON when it is created or published (the `branding` flag passed at `hooks/useCreateCatalogue.ts:22-25` sets header/footer `type`), and traffic limits are enforced later by the worker.
2. **Redis bypasses RLS.** The preview page (`app/catalogues/[name]/preview/page.tsx:28`) and `getCatalogueByName` (`actions/catalogue.ts:284-321`) serve any catalogue from Redis, including drafts and unsaved builder state, with no auth. Every Redis read needs an ownership check in code.
3. **Drizzle connects as `postgres` (BYPASSRLS).** RLS protects nothing that goes through Drizzle: newsletter signups, QR configs, `getCatalogueByName`, `fetchUserData`, the dashboard catalogue/newsletter routes, themes, AI metering. Decide first: either Drizzle stays the privileged path (code checks remain the only guard, so fix the missing ones below), or each request runs in a transaction with `SET LOCAL role authenticated` plus `request.jwt.claims`. Transaction mode on pooler port 6543 allows this.
4. **The supabase-js client depends on cookies** (`utils/supabase/server.ts:4-45`; the `createClient(false)` variant is never used). After Supabase Auth, the same client runs as `authenticated` when the request carries a session cookie (for example browser fetches of `/api/items`) and as `anon` otherwise (server self-fetches, webhooks). Policies must cover both roles, and `authenticated` has **zero grants** today. A privileged client must be a separate `@supabase/supabase-js` `createClient(url, SECRET_KEY, {auth:{persistSession:false}})` with no cookie adapter. An ssr client with cookies would send the user's JWT instead.
5. **Paths that must use a privileged client (can't be expressed as anon RLS):** the Paddle webhook (all of it), the replacement for the Clerk webhook (becomes an `auth.users` trigger), the worker (already uses service_role), and the usage check that `subscriptionProcessingJob` gets from `/api/users/[id]`.
6. **Paths that can use anon/authenticated policies:** public catalogue reads (active only), catalogue-newsletter INSERT (WITH CHECK tied to the catalogue), product-newsletter INSERT, and owner reads.
7. **Critical leaks live today.** `/api/items` returns every catalogue with `created_by`. `/api/users/[id]` and the `getUserData(userId)` server action then return any user's email, name, Paddle `customer_id` and plan. On top of that, the publishable key has broad anon grants with RLS off.
8. **PROD runs `origin/main`, which is 39 commits behind `test`.** It still ships unauthenticated `POST`/`PATCH /api/items`, `/api/analytics`, `/api/analytics/all` and `/api/subscriptions/check`, all on the anon client. Enabling RLS on PROD before `test` merges will break them. That's the right outcome, but it must be sequenced.

### Redis (`utils/redis.ts`)
- Upstash REST. Key = raw catalogue slug (no env prefix, **no TTL**). Value = JSON catalogue including `createdBy`.
- Writers:
  - `createCatalogue` (`actions/catalogue.ts:215`, the DB row)
  - `updateCatalogue` (`:256`, **unsaved builder state, no DB write**)
  - `updateItemStatus` (`:111-118`)
  - `getCatalogueByName` fill on a cache miss (`:301`, callable without auth)
  - `publishCatalogue` (`:349`)
  - `deleteItem` DEL (`:53`)
- `deleteMultipleItems` (`:79`) does **not** delete keys. The worker's inactivation (`subscriptionProcessingJob.ts:43-46`) touches neither Redis nor the Next cache.
- Readers: the preview page and `getCatalogueByName`. The public page reads the DB, not Redis.

### Catalogue statuses
- Type: `active | inactive | draft | in preparation | error` (`quicktalog-packages/src/types/enums.ts:9-14`). DB default is `'draft'`; TEST data has active and draft.
- Only `active` is public (page gate, sitemap, `generateStaticParams`). The worker sets `inactive`.

### Worker (`../quicktalog-backend`)
- No auth on any route (`src/index.ts:16-26`; `TODO.md:1` "Authorization service (Token)"). CORS is `*` and the Swagger UI is served at `/`.
- It uses a service_role supabase-js client (`src/lib/supabase.ts:4-8`), so RLS doesn't affect it.
- Cron `0 3 * * *` (`wrangler.jsonc`) runs two jobs:
  - `analyticsProcessingJob`: reads `catalogues(name, created_by)` for all rows, upserts analytics with `user_id = created_by`, inserts job_logs.
  - `subscriptionProcessingJob`: reads `users(id, plan_id)` where plan_id ≠ the free price, calls `APP_URL/api/users/{id}` without credentials, then sets `catalogues.status='inactive'` by `created_by`.
- Nothing depends on the Clerk id format. It only needs `users.id = catalogues.created_by = analytics.user_id`, and the id must be URL-safe.
- The **test env's `SUPABASE_URL` is `tpcfltcupcofteovrvmu`** (`wrangler.jsonc:28`), not TEST (`imhinsgyzzyblghwnedk`). TEST `analytics` has 0 rows.
- `/api/generate/pdf` actually dumps the D1 `logs` table and calls `/api/revalidate`. `/api/images/cleanup?delete=true` deletes UploadThing files.

### DB automation (TEST, read-only)
- `call_edge_function_with_vault_secret` is SECURITY DEFINER. It POSTs `to_jsonb(NEW)` to a **hard-coded PROD URL** (`supabase/migrations/20260911213819_remote_schema.sql:55-91`).
  - Triggers: users AFTER INSERT/UPDATE → `create-brevo-contact` (`:437`); subscriptions → `create-crm-contact` (`:441`) and `discord-subscription-alert` (`:445`).
  - TEST vault has 0 secrets, so these are no-ops there (the function skips with a warning).
  - The payload's `id` will change from `user_...` text to a uuid. The edge function source is not in any repo, and TEST has no edge functions.
- Cron "Sync Plans" posts to PROD `sync-available-plans` with a Vault bearer, which is NULL on TEST. It doesn't touch users.
- Views `contacts` and `active_subscriptions` are security_invoker, have no anon grants and are cross-user CRM exports. `contacts` does `COALESCE(u.id, lower(n.email))` and `COALESCE(u.id, gen_random_uuid()::text)`, so it will fail to type-check if `users.id` becomes uuid. `ALTER COLUMN TYPE` is also blocked while dependent views exist, so both views must be dropped and recreated with `::text` casts.
- `get_pageview_totals` is SECURITY INVOKER with anon EXECUTE. It declares `user_id uuid` but `analytics.user_id` is text, so it **errors today** (verified: 42804). Nothing on `test` calls it; only `origin/main` `app/api/subscriptions/check/route.ts` does. It would start working after a uuid migration, so drop it or revoke it from anon.
- TEST grants match the lockdown migration. The anon grants on analytics S/I, job_logs I, catalogues I/U, users S/I/U/D, subscriptions S/I/U and newsletter S are now leftovers on the test branch, because the routes that justified them were removed in 4a2f481.
- Constraints worth knowing:
  - Neither `newsletter(email, catalogue_id)` nor `product_newsletter(email)` is unique.
  - `users.email` is not unique; `users.customer_id` is.
  - `qr_configs.catalogue` is not unique.
  - `prompts.catalogue` **is** unique (`prompts_service_catalogue_key`), which breaks AI metering.
