## Summary

## External-claims fact-check of FINAL_PLAN.md (as of 2026-09-17)

I checked the third-party claims in sections 1-2, 4.7-4.8, 5, 6, 7, 8, 9.2, 10, 12, 13 and Appendices A.14, A.16 and B against four kinds of source: current official docs (Supabase, Vercel, Paddle, Clerk, Cloudflare, Resend, Next.js), supabase/auth source on GitHub master, library sources installed in the app's node_modules, and read-only SELECTs and log queries on TEST `imhinsgyzzyblghwnedk`. Most claims hold. The items that need plan changes are below, most severe first.

### Wrong or harmful as written
- **Maintenance switch (High).** Vercel renamed Edge Config to **Global Config**. A store connected now creates a `GLOBAL_CONFIG` env var, but the plan's code uses `@vercel/edge-config` and reads `EDGE_CONFIG`. It would never see the store and would silently fall back to the env var. Hobby also allows only **1 store per account** and 1 per project, 250 writes a month, and up to 10 s for a write to propagate. PROD and TEST would therefore share the same `maintenance` key unless the keys are split per environment.
- **Auth rate limits (Medium).** `/verify` and `/token` limits **can** be changed, through `rate_limit_verify` and `rate_limit_token_refresh`. Defaults are 30 and 150 requests per 5 minutes per IP, with bursts up to 30. The "360/h vs 30 per 5 min" numbers the plan saw as conflicting are the same limits written two ways.
- **Forwarding load test (Medium).** The test as written (60 `verifyOtp` calls from one tester) would get a 429 even when IP forwarding works, because all calls carry the same end-user IP.
- **Forwarded auth client (Medium).** It uses the secret key, so GoTrue treats its calls as admin: captcha is skipped. Returning the whole `.auth` also exposes `auth.admin.*` (for example `deleteUser`) outside `auth-admin.ts`.
- **Triggers on `auth.users` (Medium).** TEST's `supautils.drop_trigger_grants` lists `auth.users` for `postgres`, so `postgres` **can** drop triggers there. The PGlite stub can't reproduce supautils, which is where "cannot DROP" came from.
- **Turnstile test keys (Medium).** Cloudflare's test site keys produce a dummy token that real secret keys reject. CI and local runs that use the test site key against TEST Supabase (which has the real secret) would fail every captcha-gated call.
- **Paddle retries (Medium).** Paddle expects an HTTP 200 within **5 s**. Sandbox retries only **3 times within 15 minutes**; live retries 60 times over 3 days. TEST rehearsal events that arrive during maintenance will end up `failed` and must be replayed.
- **Paddle customer reuse (Medium).** Paddle Checkout reuses an existing customer when the same email is typed in. Resolving the user by an already-linked `customer_id` first can then credit the wrong user.
- **Clerk password timestamp (Medium).** In `@clerk/backend` 2.33.3 the `User` class has no `passwordLastUpdatedAt`; the value exists only in `user.raw.password_last_updated_at`. As written, the T-0 delta check never fires.

### Smaller corrections
- **Test setup and CI:**
  - `server-only/empty.js` is not in that package's `exports`, so a bare alias fails with ERR_PACKAGE_PATH_NOT_EXPORTED.
  - `@upstash/ratelimit` 2.1.0 needs `@upstash/redis` ≥1.38.2; 1.38.0 is installed.
- **Supabase config and logs:**
  - The Logs Explorer now uses ClickHouse SQL. I ran the corrected query on TEST and it works.
  - `uri_allow_list` is a comma-separated string.
  - I found no Management API field for "require current password" in the schema bundled with CLI 2.115, so that setting has to be made in the dashboard.
- **Auth UI and email:**
  - `signInWithOAuth` has no `captchaToken` option.
  - `{{ .RedirectTo }}` in email templates needs the app to pass a bare origin as the redirect URL.
- **Supabase CLI:**
  - `db push` also writes Vault secrets from `config.toml` unless `--skip-vault` is passed.
  - `functions download` needs Docker unless `--use-api` is passed.
- **Clerk:** the plan lists `__clerk_help`, `__dev_session` and `__clerk_hs_reason` as cookies, but they are query parameters. The real cookie `__clerk_handshake_nonce` is missing from the list.
- **Vercel functions:** with Fluid compute on, Hobby functions can run 300 s. The 60 s limit comes from `maxDuration = 60` in the agent route, or from Fluid compute being off.

### Plan claims now confirmed
Several items the plan marks "(unverified)" are now confirmed and the label can be removed:
- IP forwarding covers every IP-limited endpoint, `/token` included.
- The forwarding setting is named `security_sb_forwarded_for_enabled`, and all other auth config field names checked exist.
- Hobby honours one region set in `vercel.json`.
- Multiple named secret keys are supported.
- Transaction `custom_data` is copied to the subscription, and `Paddle.Checkout.open({ transactionId })` and `transactions.create({ items, customData })` match the installed SDKs.
- Clerk's Restricted mode still allows Backend API user creation, those emails are verified automatically, and `updateUser` accepts a password digest.
- Verifying a recovery link confirms an unconfirmed user.
- Legacy keys carry `ref` in their JWT payload (checked on TEST).
- The legacy key end date is still "late 2026, TBC".

- Whether ES256 is already the current signing key on either project.
- Which Clerk Account Portal settings can be frozen.
